# 模块界面

在 KernelSU 中打开本模块的 WebUI。0.3.0 移除原先用途不明确、点击就执行的 Action 入口。

## 应用列表

- 默认“已替换”：本模块覆盖清单中、当前仍安装且有桌面入口的应用，显示原图、替换后预览及简短原因。生效状态另行自动检查，异常条目不会从覆盖清单中消失。
- “未替换”：本模块没有覆盖的桌面应用，只显示应用图标和“未替换”。不展示未适配、素材不合适等原因；这些内容集中放在 [未纳入替换的已知情况](unsupported-apps.md)。
- “全部”：合并以上两类。支持按应用名称或包名搜索。

两类应用使用同一套行结构、图标尺寸和列宽：左侧是名称与状态，右侧是前后两栏图标。未替换应用在前一栏显示系统当前图标，后一栏以“—”占位；切换分类或查看全部时保持相同对齐。

0.3.8 起，已替换条目显示“修改原因 · 图标来源”，旁边显示生效状态。覆盖范围保留在适配文档中，不在列表中展示：

- 淘宝：`移除营销装饰 · 补全计划`
- 拼多多：`移除营销装饰 · 补全计划`
- 闲鱼：`适配自适应图标 · 补全计划`

“补全计划”表示使用完美图标补全计划的默认分层素材，“应用原图”表示使用已扫描 APK 自带的图案。底层都通过 RRO 覆盖。未替换应用不显示来源及修改原因。

应用范围来自机主用户的实时 LAUNCHER 查询，包含有桌面入口的系统应用，排除后台组件和其他用户的应用。名称与未替换应用的图标使用 KernelSU 官方包信息接口及 `ksu://icon/`，不维护固定的全部应用清单。

前后对照左侧是从匹配版本 APK 提取的位图资源，右侧是替换图标的圆形预览，不冒充当前桌面截图。应用后续更新时，左侧不会自动变成新版本的素材；页面有“原图为适配时的应用图标”说明。

闲鱼左侧是 APK 普通原图，右侧是补全计划普通前后景素材的预览；0.3.6 使用的右侧素材来自 APK。当前具体适配入口见 [覆盖情况](unsupported-apps.md)。若以后实际启用的节日入口未适配，应补充对应资源，界面只需准确报告是否生效。

拼多多电脑缓存中没有原图像素，离线预览左侧明确显示“待提取”。安装时在版本检查通过后，从已安装 `base.apk` 的 `r/cy.png` 读取原图，仅覆盖模块内对应的预览文件，保留文件权限及上下文。提取失败只保留占位并提示，不影响模块安装，也不修改原应用或备份 APK。

## 生效与清理

打开页面自动检查本模块覆盖层及实际选中的图标资源，显示“已生效／未生效／未确认”。页面没有单独的“检查状态”按钮、刷新历史或含糊的“执行”按钮。
拼多多与闲鱼还会检查系统实际启用的桌面入口 ID，并用包含拆分包的资源加载器确认该 ID 选中了本模块的自适应图标。不能再把只覆盖了一个未使用的别名视为实际生效。
仅已纳入但检查结果为“未生效”的应用显示“说明”按钮，展示实际检查得到的覆盖未启用、资源未匹配或仍选用原图标等情况。正常生效及状态无法确认的条目不显示失败说明。

唯一会改变运行状态的界面操作是“清除图标缓存”。点击后先绘制“正在清除…”和等待动画，再提交异步命令；执行中显示实际用时，列表与搜索保持可用，重复点击只提交一次。完成或失败结果保留在按钮下方，避免短暂提示消失后无法判断。打开页面、切换筛选和搜索都不执行清理。缓存删除范围、映射校准及自动清理策略不变。

`commands.mjs` 使用 KernelSU 原生 `spawn` 的 stdout/stderr/exit 协议，仅接受 `snapshot`、`clear-cache` 两种固定动作。同步启动异常、异步错误、完成回调缺失及输出上限均会结束前端等待；回调缺失显示结果未确认，不自动重试。旧管理器不支持 `spawn` 时回退到 SDK `exec`，先绘制等待状态；该回退仍可能受原生同步调用限制。

页面只调用 `ui.sh snapshot` 和 `ui.sh clear-cache` 两个固定操作，应用名及搜索内容不会拼接进 shell。应用名称和原因使用 DOM 文本节点显示。脚本、SDK、样式和对照图片离线随模块分发，不加载 CDN 或上传应用清单。

## 本地预览与测试

构建后运行 `python preview_ui.py`，生成 `dist/webui-preview.html`，可直接用浏览器打开。这个文件明确标注“界面预览”，采用模拟 KSU 接口、此前扫描的样本数据和内嵌图片，清缓存按钮不会操作手机。预览数据不进入模块 ZIP。

`npm test` 运行 Node 内置测试，不需要安装前端依赖。可选 DOM 交互测试通过 `HAPPY_DOM_MODULE=<happy-dom 的绝对模块路径> node tests/dom.mjs` 运行；可选浏览器测试通过 `PLAYWRIGHT_MODULE=<playwright 的绝对模块路径> node tests/browser.mjs` 运行。

当前环境完成了 DOM 交互验证及本机 headless Chrome 的离线预览截图，覆盖初始、等待及完成状态。预览使用模拟接口，不能代替 KernelSU WebView 真机验证。0.3.6 已通过 KernelSU 安装，重启命令成功返回；当前 0.3.8 尚未安装。
